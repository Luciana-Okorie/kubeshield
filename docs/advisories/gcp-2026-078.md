First case-study advisory for the KubeShield vulnerability engine (Phase 4).

Note on severity: third-party trackers that were found while researching score the underlying CVE at CVSS 9.8, while Google rates the GKE bulletin Medium. KubeShield should store both, labelled by source, rather than picking one.

## What the bulletin says

- The flaw can cause a kernel panic or a container escape (root code execution on the node).
- An unprivileged process in a container can trigger it locally, without special capabilities such as `CAP_NET_RAW`.
- A network attacker can also trigger it by sending TCP packets with IPv4 options to a TCP listener on a node, a Pod, or the control plane's IP-based endpoint. Clusters that restrict that access to trusted sources (firewall rules, control plane authorized networks) are not exposed to the network path.
- GKE Standard and GKE Autopilot clusters are impacted.

## Affected and fixed versions (Container-Optimized OS)

All GKE versions running Container-Optimized OS **prior to** these versions are affected. Fixed in these patch versions or later:

| Minor | Fixed in |

| 1.36 | 1.36.5-gke.1982000 |
| 1.35 | 1.35.9-gke.1505000 |

## Patch pending (as of 2026-11-05)

The bulletin states that patches for **GKE 1.37** and for **Ubuntu node images** are in progress. Versions older than 1.32 are not listed in the bulletin. The scanner must report these as `patch_pending` or `unknown`, not `patched` or `not_affected`.

## Matching rules the engine will need

1. Only GKE clusters are in scope for this advisory. Kind, EKS, AKS and self-managed clusters are `not_affected` by the GKE bulletin itself (they may still run an affected kernel; that is a different advisory source, e.g. NVD).
2. Node OS image decides which fix table applies (COS vs Ubuntu).
3. Compare the node's GKE version (e.g. `v1.35.9-gke.1505000`) per minor version, including the `-gke.<build>` suffix, not just the Kubernetes semver.
4. A missing node image or version is `unknown`.
